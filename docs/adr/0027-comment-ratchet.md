## Background: No new comments

This section was moved here from the former CLAUDE.md. Its original title: "No new comments".

**No new comments.** Code carries its meaning in names and small functions, and a decision the code cannot show goes in `docs/adr/`. `tests/comment-ratchet.sh` enforces it: a tracked code file may not hold more real comment lines than `.comment-baseline` allows (none for a file not listed). After deleting comments, tighten the baseline with `tests/comment-ratchet.sh --update`; it refuses to raise a count unless `--allow-increase` is passed, which needs a reason in the PR. The counter is `bin/comment-count.sh`, a wrapper over `bin/comment-count.py`, and it parses instead of matching lines: `shfmt --to-json` for shell (every Comment node that starts its line; heredoc bodies and multiline strings are not comments in the AST), stdlib `tokenize` for Python, and TypeScript's own parser for JS/TS (`bin/comment-count-js.mjs`, run by `node`, with `typescript` pinned in `package.json`; a comment is a range in the parser's trivia, and a line counts when its first non-blank character sits inside a comment, or is the `{` of a JSX comment `{/* */}`; a block that opens after code does not count its opening line but counts every later line it spans, and a template literal, a string, a regex or JSX text that looks like a comment is data). A file the parser cannot parse (an unclosed `/*` is one) fails the count, and so does a file that is not valid UTF-8 (the bytes are decoded strictly, never replaced), and a file with a construct TypeScript cannot read (a script with a legacy `<!--` comment at the start of a line is one; there is no retry that guesses; after code on the same line TypeScript reads it as an expression, so that form counts nothing), and so does a missing `node` or a missing `typescript` module (`npm ci`; CI runs it before every job that counts). oxlint lints the same JS and TS, the directories `bin`, `web`, `docs/demo`, `mods` and `extensions` (`npm run lint`, config in `.oxlintrc.json`, the `lint` workflow; a ratchet fixture fails when a tracked JS or TS file sits outside them); never ESLint. The trades are stated and pinned in `docs/plans/2026-11-22-chore_comment-ratchet-redesign.md`. The counter judges no grammar beyond what the parser needs to find comments: whether a file is valid JavaScript or TypeScript (a duplicate declaration, TypeScript syntax in a `.js` file) is oxlint's call, whose parser covers `.js`, `.mjs`, `.cjs`, `.jsx` and the TypeScript family, and the `lint` workflow runs it over every tracked file (a fixture compares the tracked files with the list oxlint itself prints for the lint script, `--debug=files`, so a file in an ignored directory fails it, and another pins what oxlint rejects). Four review rounds on the gate tried to make the counter a second validator (syntactic diagnostics, `node --check`, a retry for legacy comments) and each reimplemented a piece of an engine ([plan](../plans/2026-11-22-chore_oxlint-comment-parser-redesign.md)). A JSX comment line is a line that starts a JSX expression whose first token is a comment (the `{` is found in the tree, with or without a value after the comment), so a brace of a plain block never counts as one. A line ends at `\r\n`, `\n`, `\r`, U+2028 or U+2029, as in JavaScript, and a JSX comment may follow its `{` after whitespace. Declaration files count like any other file. Only the exact directive forms are exempt (`# shellcheck disable=|source=|shell=`, `# noqa`, `# type: ignore`, `# pragma:`, `// @ts-expect-error`, `// @ts-ignore`, `// oxlint-disable`), so `# pragmatism matters` is a comment. It fails closed: a file it cannot read or parse, a path with a tab or newline, a missing `shfmt` (`brew install shfmt`, `apt-get install shfmt`; CI installs it in `tests.yml` and `launchd.yml`), an empty, unreadable or malformed baseline, and any failed `awk`, `sort`, `mktemp` or `mv` in the check or in `--update` all exit 1, never a zero or a pass. `--update` builds the new baseline in a temp file beside the old one and renames it only after every step succeeded. A web-only PR still runs the ratchet (`comment ratchet, web scope` in `tests.yml`). The procedure for auditing what is left is the global `/delete-comment` skill.
