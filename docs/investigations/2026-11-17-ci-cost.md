# CI cost and feedback time, 2026-11-17

This repo's CI costs $0 because the repo is public. What it does cost is a 5-minute wait on every PR, and a weekly macOS run that stopped doing its job. The review was prompted by OpenClaw's write-up (https://vincent.build/openclaw-ci-cost-reduction/). OpenClaw runs about 1.5M jobs a week and this repo runs about 40 runs, so each of their ideas was measured here before it was adopted.

## Baseline, 2026-10-19 to 2026-11-18

`python3 docs/investigations/ci-cost/measure.py --since 2026-10-19 --until 2026-11-18`

| workflow | trigger | conclusion | runs | wall p50 | wall p90 | runner min |
|---|---|---|---:|---:|---:|---:|
| tests | pull_request | success | 85 | 5.1m | 8.9m | 1450 |
| tests | pull_request | cancelled | 25 | 2.8m | 4.7m | 334 |
| tests | pull_request | failure | 8 | 4.8m | 9.9m | 125 |
| tests | push to main | all | 38 | 5.4m | 8.2m | 667 |
| launchd | PR and push | success | 43 | 1.0m | 1.5m | 63 (macOS) |
| launchd | schedule | 1 ok, 2 failed, 2 cancelled | 5 | | | 96 (macOS) |

That is 2737 runner minutes, 159 of them on macOS. A private repo would pay for 4168 Linux-equivalent minutes.

## Findings

```
slowest shard, seconds    10-20 ▂▃   11-01 ▅   11-13 ▅   11-15 ▇█    (158 -> 392)
```

1. The weekly macOS full suite stopped running. It ran as one step inside a 20-minute job timeout. It finished in 19m58s on 11-02, then was cancelled at 20m on 11-09 and 11-16. (The 10-26 run failed on a real bug, since fixed.) For two weeks nothing ran the whole suite under bash 3.2, and that is where this repo's silent failures have come from.
2. A PR waits about 5 minutes, not the 1.5 the docs claim. Shards grew from about 150s to about 330s, mostly with the threads work on 11-14 and 11-15. The time is spread over about 280 tests and the slowest takes 28s, so there is no single test to fix. A shard job spends only about 6s beyond its tests, which means more shards cut the wait for almost no extra runner minutes.
3. The run on main retests a tree its PR already tested. For 28 of 37 pushes to main, the squash commit's tree matches the merge tree the PR's last green run tested (checked with `git merge-tree`, with main unmoved since that run). That is about 500 minutes in the window, and nobody waits on them.
4. Superseded PR runs cost 334 minutes (12%). OpenClaw's 90-second admission delay would have avoided 4 of these 25 runs (27 minutes) and added 90s to every PR. Rejected.
5. Affected-test selection has a narrow target. Of the last 80 merged PRs, 7 touched only the web dashboard: `web/`, `docs/demo/`, `docs/screenshots/`, the web Python and its tests. Their 17 runs cost 281 minutes. Every other PR reaches `run.sh`'s integration suite, where a dependency graph would almost always answer "everything". `web/threads.*` does not count as web-only, because `threads-render.py` inlines it and run-all asserts on the page it builds.

## Changes, in order

| # | Change | Expected effect | Status |
|---|---|---|---|
| A | Weekly macOS suite in 4 shards under `/bin/bash` | the full bash 3.2 run comes back, about 8 min per shard | done in this PR |
| B | Linux PR suite from 4 to 8 shards | PR wait p50 from 5.1m to about 3m, runner minutes about flat | next |
| C | Web-only selection inside each shard, full suite on anything unknown | web PRs about 1 min instead of 5, about 10% fewer minutes | next |
| D | Skip the main retest when the PR tested the same tree | about 18% fewer minutes, no change to anyone's wait | proposed, not built: it saves free minutes and adds an artifact trust path |

Ideas from OpenClaw not taken here:

- the admission delay (finding 4);
- learned or shadow test selection, since 40 runs a week is too little to learn from;
- runner right-sizing, since default runners cost $0 here;
- dependency caching, since no job installs dependencies.
